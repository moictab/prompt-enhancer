# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```
pip install -e ".[dev]"          # install app + dev deps (pytest, httpx) from pyproject.toml
pytest                           # run the full test suite
pytest tests/test_prompts.py     # run a single test file
pytest tests/test_prompts.py::test_parse_response_splits_positive_and_negative  # run a single test
uvicorn app.main:app --reload    # run the dev server at http://localhost:8000
docker compose up --build        # build and run the containerized app (reads .env, mounts ./data)
```

Copy `.env.example` to `.env` before running anything — `OPENROUTER_API_KEY`, `ADMIN_USERNAME`, `ADMIN_PASSWORD` (plus optional `DEFAULT_LLM_MODEL`/`DEFAULT_VISION_MODEL`, the models prefilled in the UI). The app refuses to start (raises in `lifespan`) if `ADMIN_PASSWORD` is unset, so tests set all three via `monkeypatch.setenv` in `tests/conftest.py`'s `api_client` fixture rather than relying on a `.env` file.

## Architecture

FastAPI + Jinja2 + vanilla JS. No build step (no bundler, no npm), no database — every persistent thing is a flat JSON or JSONL file under `data/` (gitignored, Docker-volume-mounted). `app/storage.py` is the only place that touches the filesystem for JSON: `read_json`/`write_json` (atomic via tempfile + `os.replace`) for families/characters/system prompts, `append_jsonl`/`read_jsonl`/`write_jsonl` (atomic rewrite) for history. Every domain module (`families.py`, `characters.py`, `history.py`, `system_prompt.py`) follows the same shape: a `_default_path()` derived from `get_settings().data_dir`, plain functions that accept an optional `path` override (this is how tests get isolation — `tests/conftest.py` sets `DATA_DIR` to `tmp_path` per test rather than every module needing a path argument at the call site), and no classes/ORM — just lists/dicts of plain data read-modify-written wholesale on every mutation.

**Request flow.** `app/main.py` wires a single FastAPI app with a global `Depends(require_auth)` dependency, so *every* route (including static files and page routes) is behind HTTP Basic Auth — there's no per-route auth annotation to forget. `app/auth.py` compares credentials with `secrets.compare_digest` against `Settings.admin_username/admin_password`. A middleware in `main.py` logs method/path/status/duration for every request and sets `Cache-Control: no-cache` on `/static/*` (no hashed filenames, so browsers must revalidate after a deploy); `main.py` also pins `.js` to `text/javascript`, since the frontend is ES modules and Windows can map `.js` to `text/plain`. On startup, `lifespan()` calls `seed.ensure_seed_data(data_dir)`, which creates `families.json` (seeded with SDXL and Z-Image-Turbo, each with hardcoded `*_INSTRUCTIONS` text) and an empty `characters.json` only if those files don't exist, and fills `system_prompts.json` **per mode** from `seed.DEFAULT_SYSTEM_PROMPTS` (`generate`, `iterate`, `image`, `story`, `variations`, `extract_character`): modes missing from the file are added, modes already present (edited or not) are never touched — so adding a new mode reaches existing deployments.

**`routes/api.py`** is where generation actually happens. Every prompt-crafting endpoint runs the same pipeline through shared helpers: `_require_family` (404 if unknown) → `prompts.build_system_prompt(mode, family)` (that mode's prompt from `data/system_prompts.json` + the family's instructions) → `prompts.build_user_message(mode, ...)` (where selected `character_ids` are resolved and inlined verbatim; every section heading and instruction it writes is in English, like the seeded system prompts, since the prompts themselves are English -- only the UI is Spanish, so e.g. the Variaciones axes have Spanish UI labels in `VARIATION_AXES` and English names for the LLM in `VARIATION_AXIS_NAMES`) → `_call_llm(label, model, system, user_messages, ...)` → parse → `_record(...)`, which appends the history entry and returns **the history entry itself plus `truncated` and `count_mismatch`**. So all of them respond with the same shape — `{id, timestamp, mode, family_id, family_name, llm_model, vision_model, temperature, user_input, example_prompts, previous_prompt, prompts: [{positive_prompt, negative_prompt}], cost, params, favorite, truncated, count_mismatch}` — and the frontend renders a fresh response and a history entry with the same code.
- `POST /api/generate` handles both "generate" and "iterate" (a non-blank `previous_prompt` makes it iterate; the route computes `mode` first and everything downstream follows it). `POST /api/from-image` is the vision ("image") mode. Both take `variants` (1–4): `_call_llm` makes one OpenRouter call per variant **in parallel** (`ThreadPoolExecutor`), each user message tagged with an `## Alternative` section (`variant=(i, n)`) nudging it toward its own interpretation, each parsed with `prompts.parse_response`. A failed variant is dropped (and `count_mismatch` is set); only if every call fails does the request 502. `cost` is the sum.
- `POST /api/story` (2–12 episodes) and `POST /api/variations` (2–12 variations) make a **single** call whose response holds one `POSITIVE:`/`NEGATIVE:` block per prompt, split by `prompts.parse_multi_response`; `count_mismatch` flags a different number of blocks than requested. Variaciones holds characters, an `aesthetic` and an optional base idea constant and takes `axes: [{key, vary, value}]` over `prompts.VARIATION_AXES` (outfit, setting, lighting, pose, camera, expression): a fixed axis repeats `value` (or one model-chosen option) in every prompt, a varying axis must differ across prompts (staying within `value` as hints). It also takes up to 12 `reference_prompts` (prompts the user already likes, usually of the same subject; blanks dropped): `build_user_message` puts them first under `## Reference Prompts`, numbered, with the instructions for using them (keep what they share as the constant subject, take the best of each, the rest of the request and the family rules win) -- in the user message rather than the system prompt, so existing deployments get them without reseeding. It 400s if no axis varies or nothing is held constant (references count as constant). Axis labels, and the references when given, are stored in the entry's `params` so history stays readable.
- `POST /api/extract-character` and `POST /api/extract-character-from-image` are a separate, simpler flow: the fixed `extract_character` system prompt, a `NAME:`/`TEXT:` response parsed by `prompts.parse_character_response`, returning `{name, text, cost, truncated}` for the caller to save via `POST /api/admin/characters`. Neither writes to history.
- `GET /api/history` returns entries newest-first; `PATCH /api/history/{id}` (`{favorite}`) and `DELETE /api/history/{id}` rewrite the JSONL under a lock in `history.py`. Entries written before the `prompts` list existed (a top-level `positive_prompt`/`negative_prompt`, or a story's `episodes`) are normalized on read by `history._normalize`, and migrated on disk the first time any entry is favorited or deleted.

`GET /api/openrouter-models` proxies OpenRouter's model list (`openrouter_client.list_models()`, in-process cached for `MODELS_CACHE_TTL_SECONDS`), annotating each with `supports_images` so the frontend can filter which models are offered for vision modes.

`has_negative_prompt` (set per-family in `families.json`/Ajustes) is the single flag that drives negative-prompt suppression: `prompts.parse_response`/`parse_multi_response` always parse out whatever the LLM put after `NEGATIVE:`, but force it to `""` when the family says it doesn't use one (e.g. Z-Image-Turbo, whose instructions also tell the LLM not to bother generating one — the code-level suppression is the actual guarantee, not the prompt wording). The frontend hides the negative block when it's empty.

`openrouter_client.call_openrouter` retries once (`max_attempts = 2`) when OpenRouter returns a response whose `content` is missing or not a string (a malformed-response class seen in practice, distinct from HTTP-level errors which raise immediately as `RuntimeError` with a user-facing message). `max_tokens` is 8192 and the request timeout is 180 s (a 12-prompt story or variation set takes a while and arrives in one piece); the frontend's own fetch timeout in `common.js` is set above that. Every response's `usage.cost` is threaded back through as `OpenRouterResult.cost`. `OpenRouterResult.truncated` mirrors `choices[0].finish_reason == "length"` — not retried, just surfaced so the UI can warn that a prompt may be incomplete.

**`routes/admin.py`** is a thin CRUD layer with no logic of its own — every endpoint is a one-line pass-through to `families`/`characters`/`system_prompt` functions, translating `None`/`False` returns from those modules into 404s. System-prompt endpoints are parameterized by `mode`, validated against `VALID_SYSTEM_PROMPT_MODES` (the keys of `seed.DEFAULT_SYSTEM_PROMPTS`); `GET /api/admin/system-prompt/{mode}/default` returns the seed text so Ajustes can offer "Cargar el texto original" without overwriting anything. `routes/pages.py` only renders templates: the index gets the families, the Variaciones axes (labels from `prompts.VARIATION_AXES`, initial vary/fixed from `DEFAULT_VARYING_AXES`) and the default models; historial and admin fetch their own data client-side.

**Frontend.** One Jinja2 template + one ES-module script per page, plus `static/common.js`, the one shared module: `request()` (fetch with timeout, JSON or FormData body, throws an `Error` carrying the server's `detail`), the `el()` DOM builder, `copyButton`, `setBusy`, the two-step `confirmButton` (no `window.confirm`), `toast`, the floating cost popup, and `renderTake(entry, handlers)` — the card that renders one generation (header, brief, a collapsible list of the Variaciones references with "Usar estas referencias", warnings, numbered frames with Copiar/Iterar/Añadir a referencias/Crear personaje) in both the workspace and Historial; a handler left out hides its action. It also owns the reference-prompt store (`loadReferences`/`storeReferences`/`mergeReferences` over `localStorage["reference-prompts"]`, capped at `MAX_REFERENCES`, matching the API's limit), shared because both pages add to it. The visual language (darkroom palette, the Archivo variable font served from `static/fonts/`, amber frame numbers) lives entirely in `style.css` tokens.
- `index.html`/`app.js` ("Crear"): a two-column workspace. The left composer has a mode tablist (Generar/Imagen/Historia/Variaciones) showing one `.mode-fields` block at a time over one shared form (characters, family, variants, and the collapsed model/temperature/examples section). `buildRequest()` validates per mode and returns the endpoint plus a JSON or FormData body. The right "sheet" lists the session's results newest-first (a pending card while waiting; capped at 30, persisted in `sessionStorage["workspace-takes"]`). Settings (mode, family, models, temperature, variants, examples, selected characters, story/variation counts, aesthetic and axes) persist in `localStorage["workspace-settings"]` (the pre-redesign `generar-settings` key is read once as a fallback). Characters are toggle chips plus a `<dialog>` to create/edit/delete them (through `/api/admin/characters`), which extract-character also opens prefilled. "Iterar" on any frame switches to Generar with that prompt as the starting prompt; "Añadir a referencias" appends it to the Variaciones reference list and switches there. That list is a column of textareas that always ends in one blank slot to paste into (until the limit); it is saved to `reference-prompts` on every edit and re-rendered on a `storage` event, so additions made from Historial in another tab show up live.
- `historial.html`/`historial.js`: client-side search (ideas, prompts, aesthetics, character names), mode/family/favorites filters, 25 entries per page, total cost of the filtered set. "Iterar" stashes the prompt, family, LLM model and temperature in `sessionStorage["reuse-prompt"]` and navigates to `/`, where `app.js`'s `applyReuseHandoff()` applies them. "Añadir a referencias" stays on the page (so several can be collected) and writes straight to the shared reference store; "Usar estas referencias" replaces the store with that entry's set and hands off `{mode: "variations", family_id, llm_model, temperature}` the same way.
- `admin.html`/`admin.js` ("Ajustes"): one system-prompt editor with a tab per mode, keeping unsaved drafts per mode (dirty dot on the tab, `beforeunload` guard); families and characters share the same `setupCrud()` list-plus-editor panel.

# Prompt Enhancer — Standalone Web App Design

**Date:** 2026-07-20
**Status:** Approved for planning

## Context

The project is currently a ComfyUI custom node (`comfyui-prompt-enhancer`) that calls an LLM via OpenRouter to turn a user idea into an SDXL or Z-Image-Turbo prompt. It is being replaced entirely: **the ComfyUI node goes away**, and the project becomes a small, self-hosted, single-user web application with a broader feature set. Existing logic (`openrouter_client.py`'s HTTP error handling, the SDXL/ZIT prompting rules, the response-parsing heuristics) is reused as a starting point where it still applies, but is restructured to fit the new architecture below.

## Goals

1. **Generate a prompt** from a natural-language idea, for a selectable model family (SDXL, Krea 2, Pony, ZIT, Flux, …), with optional free-text example/inspiration prompts.
2. **Iterate on a prompt** — either one generated by this tool or one pasted in from elsewhere — using the same inputs as generation, plus the prompt being modified.
3. **Generate a prompt from an image** (upload) plus the same family/example-prompt inputs, using an OpenRouter vision-capable model.

All three flows must produce a `positive_prompt` (and a `negative_prompt`, when the target family uses one) presented clearly and ready to copy.

## Non-Goals

- Multi-user support / user accounts (single shared admin password only).
- Persisting uploaded images.
- A structured/templated per-family rule schema — family instructions are free text, same spirit as the current hardcoded system prompts.
- A JS framework / SPA build step.

## Architecture

- **Backend**: Python + FastAPI + Uvicorn, single process.
- **Frontend**: Jinja2 server-rendered templates + one vanilla JS file (`static/app.js`) driving tab switching and `fetch()`-based API calls. No build step, no JS framework.
- **Persistence**: flat JSON/JSONL files under a `data/` directory, mounted as a Docker volume.
- **Config**: `.env` — `OPENROUTER_API_KEY`, `ADMIN_PASSWORD`, optional `PORT`.
- **Auth**: HTTP Basic Auth over the whole app (single shared password via `secrets.compare_digest`), chosen over a login-page/session-cookie for minimal implementation surface.
- **Deployment**: `Dockerfile` + `docker-compose.yml`, single container, `data/` as a persistent volume.

## Data Model

**`data/system_prompt.txt`** — plain text. The global system prompt: the LLM's role as an expert prompt engineer, the output format contract (`POSITIVE:`/`NEGATIVE:` markers), and general quality guidance. Always prepended to the selected family's instructions.

**`data/families.json`** — array of:
```json
{
  "id": "uuid",
  "name": "SDXL",
  "instructions": "free text: structure, length, weighting syntax, negative-prompt rules, etc.",
  "has_negative_prompt": true
}
```
`has_negative_prompt` replaces the current hardcoded `if target_model == "Z-Image-Turbo"` check: whether a family uses negative prompts becomes admin-editable data, not code. When `false`, the backend forces `negative_prompt = ""` after parsing, regardless of what the LLM returns.

**`data/characters.json`** — array of:
```json
{ "id": "uuid", "name": "Red-haired warrior", "text": "a fierce red-haired warrior in leather armor" }
```
Predefined text snippets. Available only in the **Generar** and **Iterar** tabs (not **Imagen**, which has no free-text-driven insertion point). Clicking a character button inserts its `text` verbatim into the tab's user-input textarea at the cursor position.

**`data/history.jsonl`** — one JSON object per line, appended after every successful generation (any of the 3 modes):
```json
{
  "id": "uuid", "timestamp": "ISO8601", "mode": "generate|iterate|image",
  "family_id": "uuid", "family_name": "SDXL",
  "llm_model": "anthropic/claude-sonnet-4", "vision_model": null,
  "temperature": 0.7,
  "user_input": "...", "example_prompts": "", "previous_prompt": null,
  "positive_prompt": "...", "negative_prompt": "..."
}
```
`family_name` is denormalized alongside `family_id` so history entries stay readable even if a family is later renamed or deleted. Uploaded images are never persisted — history only records that image mode was used and its textual result. History is read-only (view + copy); there is no "resume into Iterar" action from it. For `generate`/`iterate` entries, `vision_model` is `null`; for `image` entries, `llm_model` is `null` and `vision_model` holds the model used.

### Seed data

On first run (empty `data/` directory), `families.json` is seeded with two entries carried over from the current ComfyUI node's `system_prompts.py`: **SDXL** (`has_negative_prompt: true`) and **Z-Image-Turbo** (`has_negative_prompt: false`), using their existing instruction text. `characters.json` starts empty. `system_prompt.txt` is seeded with a global prompt distilled from the shared parts of the current `SDXL_SYSTEM_PROMPT`/`ZIT_SYSTEM_PROMPT` (role definition, output format contract). Krea 2, Pony, and Flux are added later through the admin panel — no instructions for them exist yet to port.

## Backend Components

- **`openrouter_client.py`** — ported from the current implementation (timeout/connection/401/402/429/malformed-response handling → human-readable `RuntimeError`s), extended to support multimodal messages: when an image is supplied, the user message `content` becomes `[{"type": "text", ...}, {"type": "image_url", "image_url": {"url": "data:<mime>;base64,<data>"}}]` instead of a plain string.
- **`prompts.py`**:
  - `build_system_prompt(family, is_iteration)` → `system_prompt_global + family.instructions + (ITERATION_ADDENDUM if is_iteration)`. `ITERATION_ADDENDUM` stays a fixed constant (structural instruction, not per-family data), ported from the current `system_prompts.py`.
  - `build_user_message(mode, user_input, previous_prompt=None, example_prompts=None)` → assembles `## Idea` / `## Prompt Previo` + `## Cambios Solicitados` / `## Prompts de Ejemplo` sections.
  - `parse_response(response_text, has_negative_prompt)` → extracts `POSITIVE:`/`NEGATIVE:` markers with the same preamble/postamble-stripping fallback as today; forces `negative = ""` when `has_negative_prompt` is `false`.
- **`storage.py`** — atomic JSON read/write (write to temp file, `os.replace`) for `families.json`/`characters.json`; append-only writer for `history.jsonl`.

### Routes

**Pages** (`routes/pages.py`)
- `GET /` — main page, tabs Generar / Iterar / Imagen.
- `GET /historial` — read-only history table.
- `GET /admin` — System Prompt Global / Familias / Personajes management.

**API** (`routes/api.py`)
- `POST /api/generate` — `{user_input, family_id, example_prompts?, llm_model, temperature}` → `{positive_prompt, negative_prompt}`.
- `POST /api/iterate` — same + `previous_prompt` (required).
- `POST /api/from-image` — `multipart/form-data`: image file + `{user_input?, family_id, example_prompts?, vision_model, temperature}`.
- `GET /api/history` — paginated history list.
- `GET /api/characters` — list of characters (for rendering buttons client-side).

**Admin** (`routes/admin.py`) — CRUD over families and characters; GET/PUT over the global system prompt.

## Request Flow (all 3 modes)

1. Client `POST`s to `/api/generate`, `/api/iterate`, or `/api/from-image`.
2. Backend validates required fields for that mode → `400 {"error": "..."}` if missing.
   - Generar: `user_input`, `family_id`, `llm_model` required; `example_prompts` optional.
   - Iterar: same, plus `previous_prompt` required.
   - Imagen: image file (multipart, `image/jpeg|png|webp`, max 10 MB) + `family_id`, `vision_model` required; `user_input`, `example_prompts` optional.
3. Loads `family` by `family_id` from `families.json` (`404` if not found) and the global system prompt.
4. `prompts.build_system_prompt(family, is_iteration)`.
5. `prompts.build_user_message(mode, user_input, previous_prompt, example_prompts)`.
6. `openrouter_client.call_openrouter(...)` (with the base64-encoded image attached for the image mode).
7. `prompts.parse_response(response, family.has_negative_prompt)`.
8. Appends the resulting entry to `history.jsonl`.
9. Returns `200 {"positive_prompt": ..., "negative_prompt": ...}`.

## Error Handling

`openrouter_client` raises `RuntimeError` with a human-readable message for network/timeout/HTTP-status errors, same as today. API routes catch this and return `502 {"error": message}` — unlike the ComfyUI node, errors no longer need to be smuggled inside the `positive_prompt` text, since the JSON response has its own error channel. The frontend renders that error as a red banner in the result panel, leaving the prompt fields untouched. Any uncaught exception is handled by a global FastAPI exception handler → generic `500`, logged server-side, no internals exposed to the client.

## Frontend

- **`base.html`** — shared layout with nav links: Prompt Enhancer / Historial / Admin.
- **`index.html`**:
  - Tabs **Generar** / **Iterar** / **Imagen**, switched client-side (no reload).
  - **Generar**: `user_input` textarea, family `<select>` (populated from `families.json` via the page context), optional `example_prompts` textarea, `llm_model` text field, `creativity` slider, character buttons next to the textarea, submit button.
  - **Iterar**: same fields plus `previous_prompt` textarea (editable by hand, or pre-filled via the "Iterar este prompt" action from a Generar result).
  - **Imagen**: file input (`accept="image/*"`) with a simple preview, optional `user_input`, family select, `example_prompts`, `vision_model` field, `creativity` slider, submit button. No character buttons.
  - **Result panel** (shared): read-only `positive_prompt` / `negative_prompt` blocks, each with a "Copiar" button (Clipboard API), and an "Iterar este prompt" button that switches to the Iterar tab and pre-fills `previous_prompt`.
- **`historial.html`** — read-only table: timestamp, mode, family, truncated/expandable prompts, copy button.
- **`admin.html`** — three sections: System Prompt Global (textarea + save), Familias (list + create/edit form: name, instructions, `has_negative_prompt` checkbox, delete), Personajes (list + create/edit form: name, text, delete).
- **`static/app.js`** — single vanilla JS file: tab switching, form submission via `fetch()`, result-panel rendering/error banners, character-text insertion at cursor position, the "Iterar este prompt" hand-off, and the admin CRUD forms.
- **`static/style.css`** — minimal custom stylesheet, no CSS framework.

## Deployment

- **`Dockerfile`**: `python:3.12-slim` base; installs `fastapi`, `uvicorn`, `python-multipart`, `jinja2`, `python-dotenv`, `requests`; copies app code; `CMD uvicorn app.main:app --host 0.0.0.0 --port 8000`.
- **`docker-compose.yml`**: single service, published port (e.g. `8000:8000`), volume `./data:/app/data` for persistence, `env_file: .env`.
- **`.env.example`**: `OPENROUTER_API_KEY`, `ADMIN_PASSWORD`.

## Testing

- `pytest` + FastAPI `TestClient` (via `httpx`) for API routes, with `openrouter_client.call_openrouter` mocked (no real OpenRouter calls in tests):
  - `/api/generate`, `/api/iterate`, `/api/from-image` — happy paths and validation errors (missing fields, unknown family, invalid image type/size).
  - Admin CRUD routes (families, characters, system prompt).
- Unit tests for `prompts.py`: system-prompt assembly (global + family + iteration addendum) and `parse_response` (with markers, fallback heuristic without markers, and forced empty negative when `has_negative_prompt=false`).
- Unit tests for `storage.py`: atomic write/read behavior.
- Manual browser verification after implementation: all 3 flows end-to-end, character insertion, "Iterar este prompt" hand-off, admin CRUD, and a full `docker compose up` run.
